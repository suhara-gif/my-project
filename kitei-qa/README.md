# 社内規程Q&A(NotebookLM連携)

就業規則・給与規程などの社内規程について、従業員が NotebookLM で口語で質問できるようにする仕組み。
**Box の規程を改定したら、NotebookLM の回答も自動で最新版に切り替わる。** 新版を手作業で
NotebookLM にアップロードし直す必要はなく、追加の費用もかからない。

## 仕組み

```
Box 規程フォルダ(直下=現行版)
   │ 1時間ごとに確認(Google Apps Script・無料)
   ▼
Googleドキュメント「社内規程_現行版(自動更新)」  ← 全規程の本文を1つにまとめて書き出す
   │ NotebookLM の自動同期(Googleドキュメントのソースは編集が自動で反映される)
   ▼
NotebookLM ノートブック(社内に共有)  ← 従業員はここで質問する
```

- **最新版の判定:** Box の規程フォルダ(`【共有】全社共通フォルダ/01_社内規程`)の**直下にあるファイルを
  現行版とみなす。** サブフォルダ(「旧フォルダ」)の中は読まない。いまの運用(新版を直下に置き、
  旧版は旧フォルダへ移す)をそのまま使う。
- **1つのドキュメントにまとめる理由:** 規程は改定のたびに別ファイルとして Box に置かれている
  (例: `就業規則_20250401改定.pdf`)。ファイルごとにドキュメントを作ると、改定のたびに
  NotebookLM へソースを追加し直す必要がある。1つにまとめれば、ソースは最初に1回追加するだけで済む。
- **本文の取得:** Box が自動生成するテキストを使う。文字データの無いスキャン画像PDFは、ページ画像から文字認識する(下記)。
- **変更がないとき:** Box のファイル一覧を確認するだけで終わる。変更があったときだけドキュメントを書き直し、
  スクリプトの所有者にメールで知らせる(取り込めた規程・読めなかった規程の一覧つき)。
- **Box の認証:** Box のサーバー認証アプリ(Client Credentials Grant)を使う。アプリ専用の
  サービスアカウントを規程フォルダに「ビューアー」として招待するので、このスクリプトが読めるのは
  そのフォルダだけになる。

## 技術選定の経緯

| 案 | 採否 | 理由 |
|---|---|---|
| Box AI | 不採用 | 契約に含まれていない(須原さん確認済み) |
| Claude のスキル + Box コネクタ | 不採用 | Claude のアカウントを持っていない従業員がいる(須原さん確認済み) |
| GAS Webアプリ + Claude API | 不採用 | 動くが、API の従量課金(試算で1問あたり数十円)がかかる。追加費用なしの方針に合わない |
| **Box → Googleドキュメント → NotebookLM** | **採用** | NotebookLM はすでに使っており、Google Workspace の契約内で追加費用なし |

NotebookLM は2026年5月から、Googleドキュメント・スプレッドシート・スライドのソースについて、
Drive上の変更を自動で取り込むようになった([Google Workspace Updates](https://workspaceupdates.googleblog.com/2026/05/keep-your-sources-up-to-date-with-automatic-Drive-syncing-in-NotebookLM.html))。
PDFなどアップロードしたファイルは自動同期の対象外のため、Googleドキュメントに変換して渡している。

## スキャン画像のPDFについて

規程フォルダの就業規則本体2件(アプティ 20250401改定、アプティグローバル 20250301制定)は、複合機でスキャンした
画像PDFで、文字データが入っていない。Box が自動生成するテキストは空になるため、**ページ画像から文字認識(OCR)して
取り込む。** PDFを差し替える必要はない。

- Box が生成するページ画像(PNG)を1ページずつ取得し、Googleドライブの文字認識(画像→Googleドキュメント変換)にかける。
  費用はかからない。PDFを丸ごと変換しないのは、ドライブの文字認識に2MB・10ページまでといった制限があるとする解説があり、
  19ページ・5.2MBの就業規則は収まらない見込みのため(1ページずつなら収まる)。
- 認識結果はページごとにドライブ(`社内規程Q&A_文字認識キャッシュ` フォルダ)へ保存する。同じ版は二度と認識し直さない。
  1回の実行(約4分半で打ち切り)で終わらなくても、次の実行で続きのページから再開する。
- 取り込みが終わるまではドキュメントを書き換えない。改定直後に、就業規則がまるごと抜けた状態で NotebookLM へ
  同期されるのを防ぐため。24時間以上終わらない場合は、管理者にメールで知らせる。
- 文字認識した規程には、ドキュメント上で「数字や語句を読み間違えている可能性がある」旨の注記を付ける。
  NotebookLM がPDFを直接読む場合も内部で文字認識しているので、精度の考え方は今と同じ。
- 今後の改定で、元データから書き出した(文字の入った)PDFを置けば、文字認識を使わずに正確に取り込める。必須ではない。

- NotebookLM がドキュメントの変更を取り込むまでの時間。Google の告知に具体的な間隔の記載がない。[要確認]
- Box の契約プランで、カスタムアプリ(サーバー認証)を作成・承認できること。[要確認]

  就業規則には従業員への周知義務があるので、全員に見せて問題ないという前提。ただし、規程フォルダに
  周知対象外の文書を置くと、その本文も全員に見える点に注意。

  抜き取りで確認すること。[要確認]
- スキャンPDFは横向き(90度回転)で保存されている。Box が生成するページ画像が正しい向きになっているか、
  初回の取り込み結果で確認すること(文字化けした内容になっていれば向きの問題)。[要確認]
