# セットアップ手順

上から順に進めてください。手順1は Box の管理者が、手順2以降は Google Workspace の会社アカウントで作業します。
画面の名称は、各サービスの更新で変わることがあります。

## 1. Box: 規程を読むためのアプリを作る

1. Box の開発者コンソール(https://app.box.com/developers/console)を開き、「アプリの新規作成」を選ぶ。
2. 「カスタムアプリ」→ 認証方法は「**サーバー認証(クライアント資格情報許可)**」を選ぶ。
   アプリ名は「社内規程Q&A」など。
3. 作成したアプリの「構成」タブで次を設定して保存する。
   - アプリアクセスレベル: **アプリアクセスのみ**
   - アプリケーションスコープ: **Boxに格納されているすべてのファイルとフォルダの読み取り**だけにチェック(書き込みは不要)
4. 「承認」タブからアプリを送信し、Box管理者が管理コンソール(「統合」→「Platformアプリマネージャー」)で承認する。
5. 「一般設定」タブに表示される**サービスアカウントのメールアドレス**(`AutomationUser_...@boxdevedition.com` の形式)を控える。
6. Box で `【共有】全社共通フォルダ/01_社内規程` を開き、手順5のメールアドレスを**ビューアー**として招待する。
   - 招待するのは規程フォルダだけにしてください。スクリプトが読めるのはこのフォルダだけになります。
7. 次の4つを控える(あとでスクリプトプロパティに入れます)。
   - クライアントID、クライアントシークレット(「構成」タブ)
   - Enterprise ID(「一般設定」タブ、または管理コンソールの「アカウント情報」)
   - 規程フォルダのID: フォルダを開いたときのURL `https://app.box.com/folder/【ここ】` の数字。
     2026-10-08 時点では `131041036361`

クライアントシークレットはパスワードと同じ扱いです。チャットやメールに貼らないでください。

## 2. Apps Script プロジェクトを作る

この作業をした人が、スクリプトとドキュメントの所有者になり、更新通知のメールを受け取ります。
退職や異動の予定がない管理担当者のアカウントで作業してください。

1. Google Drive で「新規」→「その他」→「Google Apps Script」を選び、名前を「社内規程Q&A」にする。
2. 左のファイル一覧で、次のファイルを作り、`kitei-qa/src/` 配下の同名ファイルの中身をそれぞれコピペする。

| Apps Scriptで作るファイル | 中身のコピー元 |
|---|---|
| `Code.gs`(最初からあるものを流用) | `src/Code.gs` |
| `Box.gs`(「+」→「スクリプト」) | `src/Box.gs` |
| `Ocr.gs`(「+」→「スクリプト」) | `src/Ocr.gs` |

3. 左の歯車アイコン(プロジェクトの設定)→「『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにし、
   `appsscript.json` の中身を `src/appsscript.json` に置き換える。
   - これで、文字認識に使う「Drive API」サービスも有効になります(左の「サービス」に Drive が表示されます)。

## 3. スクリプトプロパティを設定する

歯車アイコン(プロジェクトの設定)→「スクリプト プロパティ」に、次を追加して保存します。

| プロパティ | 値 |
|---|---|
| `BOX_CLIENT_ID` | 手順1-7のクライアントID |
| `BOX_CLIENT_SECRET` | 手順1-7のクライアントシークレット |
| `BOX_ENTERPRISE_ID` | 手順1-7のEnterprise ID |
| `BOX_FOLDER_ID` | 規程フォルダのID |

`DOC_ID`・`LAST_SIGNATURE`・`OCR_FOLDER_ID`・`PENDING_SINCE` はスクリプトが自動で追加します。手で作ったり消したりしないでください。

スクリプトプロパティはプロジェクトの編集者なら誰でも見られます。編集者は管理担当者だけにしてください。

## 4. 初回の同期と自動実行の設定

1. エディタ上部の関数選択で `syncRules` を選び、「実行」を押す。初回は権限の承認画面が出るので許可する。
   - スキャン画像のPDFは1ページずつ文字認識するため、初回は数分かかります。約4分半で一度打ち切るので、
     メールが届かないまま終わった場合は、もう一度 `syncRules` を実行してください(続きのページから再開します)。
2. すべて取り込めるとメールが届きます。
   - 取り込めた規程と、読み取れなかった規程の一覧が載っています。
   - メール内のリンクから、Googleドキュメント「社内規程_現行版(自動更新)」を開いて中身を確認してください。
   - 「(文字認識)」と付いた規程は、元のPDFと見比べて、日数・金額・条番号に読み間違いがないか抜き取りで確認してください。
   - 新しくアップロードした直後のファイルは、Box側の準備が終わっておらず読めないことがあります。
     その場合は数分おいて `forceResync` を実行してください。
3. 関数選択で `setupTrigger` を選び、「実行」を押す。以後、1時間ごとに自動で確認します。

## 5. NotebookLM に登録して共有する

1. NotebookLM で新しいノートブックを作り、名前を「社内規程Q&A」などにする。
2. 「ソースを追加」→「Google ドライブ」から、ドキュメント「社内規程_現行版(自動更新)」を追加する。
   - **ソースはこのドキュメント1つだけにしてください。** 以前アップロードしたPDFなどが残っていると、
     古い内容で答えてしまいます。いまお使いのノートブックを流用する場合は、古いソースを削除してください。
3. ノートブックの「共有」から、社内の全員に共有する(閲覧のみ、またはチャットのみ)。
4. 共有リンクを従業員に案内する(社内ポータルやSlackのブックマークなど)。

ノートブックの「カスタマイズ」で回答の指示を設定できます。例:

> 社内の従業員からの質問に答えます。ソースに書かれている内容だけを根拠に、規程名と条番号を示して
> 話し言葉で答えてください。ソースに記載がない場合や「読み取れなかった規程」に関する質問の場合は、
> 推測せず人事・総務への確認を案内してください。会社(アプティ/アプティグローバル)や雇用形態で
> 規程が異なる場合は区別して答えてください。

## 規程を改定したとき

NotebookLM やスクリプト側の作業は不要です。

1. 新しい規程を規程フォルダの直下に置く。スキャンしたPDFでも取り込めますが、元データから書き出したPDFなら文字認識の読み間違いがありません。
2. 古い版を「旧フォルダ」へ移す。**直下に新旧両方が残っていると、両方を現行版として取り込んでしまいます。**
3. 1〜2時間以内に更新通知のメールが届きます(スキャンPDFは文字認識に時間がかかります)。
   「読み取れなかった規程」に新しいファイルが入っていないか確認してください。

## コードを更新したとき

Apps Script のコードを貼り替えるだけで、次回の自動実行から反映されます。
