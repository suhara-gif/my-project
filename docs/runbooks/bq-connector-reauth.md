## A. 管理コンソールで、再認証の期限を確認する(最優先・設定変更の前に確認だけ)

仮説: Google Workspace の「Google Cloud セッション制御」が、ユーザーOAuthの BigQuery アクセスに、一定時間ごとの再認証を求めている。
再接続から約1日以内は書き込めて、それを過ぎると必ず止まる、という観測(10/09 18:52→10/10 08:52 は成功、10/11 08:53 は失敗)と合う。[未確認]

1. Google 管理コンソール → セキュリティ → アクセスとデータ管理 → **Google Cloud のセッション管理**(英語表記: Google Cloud session control)。
2. 対象の組織部門(須原さんのアカウントが属する部門)を選ぶ。
3. 「再認証の頻度(セッション時間)」を見る。
   - 「再認証を要求しない」以外(1時間〜24時間など)になっていれば、仮説に合う。
   - 「再認証を要求しない」なら、仮説は外れ。別の原因を調べる(私に知らせてください)。
4. 変更する場合の選択肢(情報システムの方針に従う)。
   - 期間を延ばす、または「再認証を要求しない」にする。
   - 信頼済みアプリ(API の制御 → アプリのアクセス制御)として、コネクタの OAuth クライアントを登録し、再認証を免除する。
     クライアントIDは、接続時の同意画面または Anthropic のコネクタ設定で確認する。[未確認: 私は値を持っていません]
5. 変更しない場合は、次の B・C を再承認する。

戻し方: 3 の設定を元の値に戻す。変更前の値は、メモしておく。

## 次の判定条件(R2): 仮説の当否は、数値で判定する
- 再接続した時刻を T とする。T から24時間以上たった後の定期実行(08:52 前後)が、`raw_ad_daily` に書けているかで判定する。
  確認は、`fetched_at`(JST)の最新値が、その日の 08:5x になっているか。私が読み取りで確認する。
- 書けていれば、期限が延びた(または免除された)。仮説に合う。
- 書けていなければ、仮説は外れ。B・C に進む。

## B. 書き込みをサービスアカウントへ移す(未適用・IAM の変更が要る)
