# 列を文字で固定して読むGASは、列を1つ足しただけで「完了」のまま壊れる

## 何が起きたか
- トヨワクの会員の流入元(SF `sourceMedium_j_tw__c`)が 10/6 以降ほぼ全件空欄になった。
- 原因は GAS `TwMediaSync.gs`(`twSyncMediaFields`)が「流入後突合tw」を `O`/`P` と列の文字で読んでいたこと。須原さんがシートに列を1つ足したため、O列に日付、P列に参照元メディアが来た。
- 参照元メディアは辞書に無い値として全件スキップ、広告タイプ項目には参照元メディアの名前が約1,540件書き込まれた。実行結果は毎日「完了」で、誰も気づかなかった。

## どう突き止めたか(次に同じ症状を見たときの順番)
1. SFで「いつから空欄か」を日別に出す(流入日×流入元の GROUP BY)。境目の日を決める。
2. 同じ時期に止まった別の書き込み(今回は `ContactExtended_JS__c` の書き込み時刻)と、SF `LoginHistory` の連携アプリのログイン時刻を突き合わせ、どの処理かを絞る。ログインが成功していれば認証切れではない。
3. Apps Script の「実行数」で該当関数のログを開く。「完了」でも中身のログ(今回は「辞書未収録のためスキップ: label=[日付]」)を見る。
4. Notion の設計ページで、その関数が読む列・項目を確認し、ログの値と照合する。

## 再発防止の考え方
- シートの列は文字ではなく見出し名で探す。
- 読んだ値の型が想定と違う(参照元メディア列に日付が入っている等)ときは、スキップではなく例外にして実行結果を「失敗」にする。「全件スキップで完了」は監視に引っかからない。
- 「既存値は上書きしない」作りは、誤った値を一度書くと直しても残る。修正後に誤記入の掃除が要る。
