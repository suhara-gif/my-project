# 「勝ちCR」の定義に合わない主力CRの停止を検知が素通りした

## 状況
35日の後ろ向き検証で、最大費用の ASC_ブランド訴求16_整備士(¥177k・登録13件)が直近7日で配信ゼロになったのに、
`winner_dropout` が鳴らなかった。

## 原因
`is_winner` は「縮約CPA ≤ 目標CPA」を要求する。目標 ¥5,800 は整備士CPAからの暫定換算で、
この広告の登録CPA(¥13,637)はそれより悪い。「勝ち」の定義が暫定値に依存していたため、
配信構成を大きく変えた主力CRの停止が検知対象から外れた。

## 対処
費用はCVと違ってノイズが小さい。基準期間にキャンペーン費用の15%以上を占めたCRの停止は、
勝ち負けによらず `major_dropout` として通知する(`detect_winner_dropout` の `baseline_spend_share`)。

## 次に効く考え方
検知条件に「暫定値で決めた分類(勝ち/負け)」を挟むと、その暫定値の誤差がそのまま検知漏れになる。
ノイズの小さい量(費用・シェア)で足りる検知は、分類を挟まず量で書く。
