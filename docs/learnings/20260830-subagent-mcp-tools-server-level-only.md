# サブエージェントのMCPツール権限はサーバー単位でしか絞れず、最小権限設計に上限がある

- 日付: 2026-08-30
- 種別: 設計判断 / 調査
- 触れたファイル: .claude/agents/up-verify-reviewer.md, .claude/agents/up-check-runner.md, .claude/commands/up-verify.md, .claude/commands/up-check.md

## 問題

`up-verify`(検品コマンド)を独立コンテキストのサブエージェント`up-verify-reviewer`に切り出す際、
`tools: Read, Grep, Glob`に絞ることで「検品するだけで書き換えない」という指示文だけの制約を、
編集権限を持たせない物理的な強制に格上げできた。この成功パターンを、次に`up-check`(広告データ
点検コマンド)のサブエージェント化にもそのまま適用しようとしたところ、同じようにはいかなかった。

`up-check`はGoogle Drive・Meta Adsの読み取りと`company/secretary/nippou/`への書き込みが必須で、
`tools`にMCPサーバーを含める必要がある。ところが`tools: mcp__Meta_Ads`と書くと、点検に使う
`ads_get_*`/`ads_insights_*`のような読み取り系ツールだけでなく、広告の作成・削除・更新・
予算変更のようなツールまで丸ごと許可されてしまった。

## 文脈

公式ドキュメント(sub-agentsのMCPツール指定仕様)には次のように明記されている。

> You do not list individual tool names like `mcp__Google_Drive__search_files`—use the
> server name only

つまり`tools`/`disallowedTools`はどちらも**MCPサーバー単位**でしか制御できない。個別ツール名
(例: 読み取り専用の`ads_get_ad_entities`だけ許可し、書き込み系の`ads_create_campaign`は除外する)
という粒度の指定はできない。`up-verify-reviewer`が成功したのは、ビルトインツール(Read/Grep/Glob)
は個別に指定できるためで、MCPサーバーに依存するタスクでは同じ設計が通用しない。

## 解法と、その理由

物理的に防げない以上、サブエージェント本文(システムプロンプト相当)に「読み取り専用ツールのみ
使う。書き込み系ツールは絶対に使わない」と明記する、指示文ベースの制約に留めた。これは
up-verifyで実現した「精神論から強制層への格上げ」という理想には届かないが、次の理由でこれ以上
の対処はしなかった:

- Meta Ads/Google Driveへのアクセスをメインセッション側で先に取得し、テキストだけをサブエージェント
  に渡す設計も検討したが、それだと巨大シートのデータそのものがメインの会話コンテキストを消費して
  しまい、そもそもサブエージェント化した動機(コンテキスト分離)が失われる。
- この矛盾(最小権限 vs コンテキスト分離)は、up-checkのように外部データ取得が本質的に必要な
  タスクでは構造的に生じるため、どちらかを完全に諦める必要がある。今回はコンテキスト分離を優先し、
  権限の絞り込みは指示文に委ねた。この判断はPR本文に明記してユーザーに委ねた。

## うまくいかなかったこと

- `disallowedTools`でMeta Ads内の書き込み系ツールだけを除外しようとしたが、これもサーバー単位
  でしか指定できず、個別ツールの除外はできなかった。
- 副次的に、以下も観測したが原因は未特定([要確認]のまま):
  - 新規`.claude/agents/`ディレクトリでなくても(既存ディレクトリへの追加でも)、ファイル追加後に
    Agent toolの`subagent_type`として認識されるまで、複数ターン・複数回のリトライを要した。
    公式ドキュメントは「detects the change within a few seconds」と説明しているが、実測はそれより
    明らかに長くかかった。
  - 同一セッション内で`up-verify-reviewer`と`up-check-runner`という2つのカスタムサブエージェント
    を作ったところ、両方が同時にAgent type一覧に載ることがなく、片方が使えるようになると
    もう片方が「no longer available」と表示された。
  - Google DriveのMCPツールでファイルの「メタデータだけ」を取得しようとしても、スプレッドシートの
    場合は`contentSnippet`として本文冒頭のデータが一緒に返ってくる仕様があり、「全文は取得しない」
    という指示だけでは防げなかった。

## 抽出したルール / ヒューリスティック

**サブエージェントの`tools`にMCPサーバーを含める設計をする前に、そのサーバーに破壊的操作
(作成・削除・更新系)のツールが同居していないか確認する。同居している場合、`tools`による
物理的な権限の絞り込みは実現できないと判断し、(a)指示文で使用範囲を明記する、
(b)そのサーバーへのアクセスをメインセッション側に残しサブエージェントには渡さない、
の二択のどちらを取るかを設計判断としてPRやコミットメッセージに明記する。**
「サブエージェント化すれば自動的に最小権限になる」と思い込まない。
