# 監視の仕組みは、監視対象と同じ壊れ方をしない形で作る

- 日付: 2026-09-28
- 種別: 設計判断
- 触れたファイル: ad-monitor-board/src/Board.gs、ad-monitor-board/README.md

## 問題

`GAS_広告実績、今年RAW` の `daily_summary` は日次・媒体×サイト別の数字の羅列で、変化や異常に
気づきにくい。これを視覚的に把握できる仕組みにしたい、という依頼だった。

## 文脈

このブックまわりでは、GASジョブが気づかれずに止まる事故が繰り返し起きていた。
7/11の集計スクリプト失敗、AIシグナルシートの17日間停止、2026-09-19〜24のカーワーク整備士CV
オフラインアップロードの6日間停止(これはGoogle広告APIの `offline_conversion_upload_conversion_action_summary`
の `daily_summaries` で、毎日1:00台に実行されていたものが途切れたことを確認して発見した)。
また `daily_summary` 自体にも、直近約31日分しか持たない、最終行が集計途中(当日分)になっている、
全期間空欄の列がある、という性質があった。

## 解法と、その理由

- **ボードを数式だけで作り、定期実行ジョブを増やさなかった。** GASのジョブで毎朝ボードを書き出す方式にすると、
  そのジョブ自体が監視対象と同じ理由(実行失敗・トリガー切れ)で黙って止まる。数式なら
  `daily_summary` が更新される限り連動し、止まる要素が増えない。
- **シート参照を `INDIRECT` にし、列は見出し名で `MATCH` した。** 集計ジョブがシートを消して作り直したり、
  列を挿入したりしても参照が壊れない。
- **最終行が今日以降なら判定に使わない。** 集計途中の行を「昨日」にすると、ほぼ全行が
  「費用が平均より少ない」になり、ボードが常に赤くなって誰も見なくなる。
- **全期間空欄の列は「データなし」として要確認から外した。** 毎日同じ行が要確認に出続けると、同じく
  ボードが無視される。
- **判定は「異常」ではなく「要確認」に留めた。** 空欄の原因は4種類ありうる(business.md「空欄の読み方」)ため、
  ボードが断定しないようにした。
- 既存の集計スクリプトと同じプロジェクトに置く可能性があるため、グローバル名を `MB_` / `mb` 接頭辞にし、
  `onOpen` を定義しなかった。GASは全ファイルでグローバル名を共有するので、`CONFIG` や `onOpen` が
  ぶつかると既存の集計を壊しうる。

## うまくいかなかったこと

- 最初の案は比較基準を28日にしていたが、シートには31行しか無く「除外3 + 今7 + 基準28 = 38日」が収まらない。
  見出しを実物で確認してから14日に縮めた。
- 整備士の列名を「整備士」と仮置きしていたが、実物は「整備士CV」だった。**列名を仮置きしたまま
  数式を組むと全行が空欄になる**ので、実物の見出しを取ってから確定させた。
- Google Sheets 上で実行できる環境が無いため、GAS呼び出しを node で模擬して数式を生成・目視し、判定ロジックは
  Python で実データに当てはめて確認した。シート上での実動作は未確認で、セットアップ手順に確認項目として残した。

## 抽出したルール / ヒューリスティック

監視の仕組みを作るときは、「監視対象が壊れる理由(ジョブ停止・シート再作成・列移動・集計途中の行)で
監視側も壊れないか」を1つずつ確認する。新しい定期実行ジョブを足すのは、それ以外の方法が無いときだけにする。
また、要確認が常に出続ける行(全期間空欄・集計途中の行)を先に除外しないと、ボードは数日で見られなくなる。
