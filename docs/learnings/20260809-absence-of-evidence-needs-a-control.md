# 不在証拠から因果を推論する前に、必ず対照試験を1本入れる

- 日付: 2026-08-09
- 種別: 調査 / 失敗した試み
- 触れたファイル: company/knowledge/business.md、.claude/commands/up-check.md、company/secretary/nippou/2026-08-09-healthcheck.md

## 問題

広告実績シート `daily_summary` の `M_CW_費用`（Metaカーワク）が 2026-07-15 から 8/8 まで25日間空欄だった。
「配信停止なのか、取得漏れ（集計の故障）なのか」を切り分ける必要があった。両者で打ち手が正反対になる
（停止なら異常なし、取得漏れなら緊急）。

Gmail の Meta 領収書メールを調べたところ、7/14以降の23スレッドに CW アカウント(723299057330625)が
1通も無く、他4アカウント（CWA/TW/MW/OS）は全て届いていた。しかも 8/4 に CWA で ¥1,732 という
少額請求が届いており「少額でも領収書は飛ぶ」ことが確認できた。
そこで **「領収書ゼロ＝課金ゼロ＝配信停止の公算大」** と結論し、ナレッジ正本 `business.md` に
切り分けルールとして書き込んだ。

独立検品（別エージェント）がこれを反証した。CW アカウントの領収書は「7/14以降ない」のではなく、
**Gmail 全期間・全フォルダで1通も存在したことがない**（`in:anywhere 723299057330625` で0件。
同じ検索で MW は201件ヒットするので検索側の不備ではない）。一方シート自身は 7/10〜7/14 に
CW Meta 費用 ¥8,415 を記録している。つまり **課金が確実にあった期間ですら領収書は来ていなかった**。

## 文脈

なぜ非自明だったか: 「少額でも領収書は届く」という補強事実を1つ掴んでいたため、推論が正しく見えた。
実際その事実自体は正しい（CWA では ¥1,732 の領収書が実在する）。**正しい一般則を、それが成り立つか
未確認の個体に適用した**のが誤り。CW アカウントだけ通知設定・請求先・登録状態が違う可能性を潰していなかった。

制約: Meta 広告の管理画面へ直接つなぐツールは承認が通らず、間接証拠に頼らざるを得ない場面だった。
それでも「間接証拠しか無い」ことと「間接証拠で断定してよい」ことは別だった。

## 解法と、その理由

**不在証拠（Xが無い）を前提に因果を語る前に、対照試験を1本入れる**というルールを立てた。

具体的には「**正常時にはXが有ったのか**」を先に確認する。今回なら
`from:business-updates.facebook.com 723299057330625 in:anywhere`（期間を切らずに全期間）を先に叩く。
0件と分かった時点で、領収書は CW について**何の情報も持たない**と判定でき、誤った結論を書かずに済んだ。

なぜこの形にしたか: 「慎重に考える」「断定を避ける」といった心構えでは再発を防げない（実際このセッションでは
同種の誤りを3回繰り返した: ①CWA「大失速」誤り ②「パイプライン不調が最有力」誤り ③今回）。
**実行できる1手順（対照クエリを先に叩く）**に落とさないと守れない。

あわせて、空欄の解釈を1対1対応の表（空欄→停止 / 空欄→異常）から、
**原因4種を列挙して順に潰す手順**へ置き換えた。表の形式そのものが断定を誘っていた。

## うまくいかなかったこと

- **費用列だけを見て「Google Ads API v21 サンセット(8/5)の実害なし ✅」と締めた。** 同じ検品で
  `G_CWA_CV` が 8/1〜8/6 の6日連続空欄（7月の最長は2日）と判明。**費用は取れるがCVだけ落ちる**のは
  API 断で最も起きやすい壊れ方で、見るべき列を外していた。しかも自分が書いた点検ルール
  「CV空欄2日以上」に該当しながら報告していない。**チェック項目を書いた本人が、そのチェックを実行しなかった。**
- **「他媒体が正常＝パイプライン全体は生存」と一般化した。** 同一ファイル内の AIシグナルシート
  （毎日8:24更新）は 7/23 で止まり17日沈黙していた。見た範囲を「全体」と言い換えていた。
- **CPA急騰を「検出せず」と報告した。** 実際は G_TW_CPA 8/1 が直近7日平均の3.17倍。
  倍率を計算せず目視で済ませたため見落とした。

## 抽出したルール / ヒューリスティック

1. **「Xが無いからYだ」と書く前に、「正常時にXは有ったか」を確認するクエリを1本先に叩く。**
   確認していなければ、その推論は書かない。
2. **数値の異常判定は必ず計算する。** 「急騰」「急減」を目視で判断しない。倍率・増減率を出す。
3. **報告には「何を見て、何を見ていないか」を書く。** 見た範囲を「全体」と言い換えない。
4. **自分が定義したチェック項目は、実行してから結論を書く。** 項目を書くことと通すことは別。
5. 空欄・ゼロ・欠測は、1対1対応の表で解釈しない。**原因を複数列挙して潰す手順**にする。
