# Slack の増分同期で、スレッド返信と DM が漏れる理由と対処

- 日付: 2026-09-24
- 種別: 設計判断 / 調査
- 触れたファイル: slack-notion-archiver/設定と同期.gs, slack-notion-archiver/コード.gs

## 問題
Slack → Notion 保存 GAS で「返信と DM も保存したい」と依頼された。元コードは DM(`im`/`mpim`)を
取得対象の type に含めていたので、一見すると DM は保存済みに見えた。

## 文脈
次の3つは、コードを見ただけでは気付きにくい。
1. **Bot トークン(`xoxb-`)は Bot が参加している会話しか読めない。** `types` に `im` を書いても、
   人同士の DM は一覧に出てこない。エラーにもならないので、保存されていないことに気付けない。
2. **`conversations.history` はトップレベルのメッセージしか返さない。** しかも `oldest` は親の ts で絞られる。
   そのため、前回位置より前に立ったスレッドへの新しい返信は、親ごと取得範囲の外に落ちる。
3. **全体で1つの `LAST_TS` を「見えた最大 ts」まで進める方式は、次の3経路で取りこぼす。**
   Notion 保存の失敗、チャンネルごとの取得時刻の差(時計ズレを含む)、実行時間切れ。

## 解法と、その理由
- **DM**: ユーザートークン(`xoxp-`)を任意で追加した。チャンネルは従来どおり Bot で読み、
  Bot が読めない会話(DM、グループ DM、自分だけのプライベート CH)だけをユーザートークンで読む。
  全部をユーザートークンに切り替える案もあったが、退けた。Bot の公開 CH 自動 join で得ていた
  範囲が狭まるうえ、ユーザートークンで join すると本人が勝手にチャンネルへ参加してしまうため。
- **返信**: history を `min(前回位置, now-7日)` から読み、その範囲に立ったスレッドの親を拾う。
  親の `latest_reply > 前回位置` のものだけ `conversations.replies`(oldest=前回位置)を呼ぶ。
  条件で絞るのでAPIの呼び出し回数を抑えられる。
  - `thread_broadcast` はトップレベルと返信の両方に現れる。二重保存を避けるため、返信側でだけ拾う。
- **進捗**: 会話ごとに `LAST_TS_<id>` を持つ。
  - 取得範囲の上限は `latest = now-60秒` に固定する。
  - 時系列順に保存し、失敗や時間切れで止まったら「最後に保存できた ts」までしか進めない。
  - 同じメッセージで3回失敗したら、そのメッセージは諦めて先へ進む。永久に詰まるのを防ぐため。
  - 旧 `LAST_TS` は、個別の進捗がまだ無い会話の開始位置として引き継ぐ。移行時に重複も欠落も出ない。
- Node で GAS API をモックし、次を確認した。
  古いスレッドへの新しい返信を拾う/前回位置より前の返信は拾わない/直近60秒の投稿は次回に回す/
  保存に失敗したら次回再試行する/2回目の実行で重複しない。

## うまくいかなかったこと
なし。Slack 実環境での動作は未検証(トークンのスコープやワークスペースの承認設定はこちらから見えない)。

## 抽出したルール / ヒューリスティック
- Slack で「DM も取る」実装を見たら、**使っているトークンが `xoxb-` か `xoxp-` かを最初に確認する。**
  `xoxb-` なら、人同士の DM は取れていない。
- `oldest` で増分取得する同期を見たら、**「古い親への新しい子(返信・コメント)」を取れているか**を必ず確認する。
- 増分の進捗は「見えた最大値」ではなく、**「最後に保存が確定した位置」と「取得に使った上限」**で進める。
