# キャンペーン単位のファネル分解は、広告の入れ替わりを「段の崩れ」と取り違える

- 日付: 2026-09-28
- 種別: 失敗した試み / 設計判断
- 触れたファイル: meta-ads-autopilot/src/meta_autopilot/detect/funnel.py, detect/fatigue.py

## 問題
キャンペーン単位で CPM→CTR→LPV率→CVR を分解する異常検知を、トヨワクの実データ(2026-08-24〜09-27)に通した。
ASCキャンペーンで「CVR 1.97%→0.36% の崩れ。候補: LP・フォーム変更、計測不具合」と出た。

## 文脈
広告別に分けると、実際の原因は別だった。勝ちCR(ブランド訴求16_整備士: CV13件)の費用が直近7日で0になり、
新CR(転職相談_動画_地域)に費用の半分以上が寄っていた。CVR 不足分の88%はこの新CRによるもの。
キャンペーン合計では、構成の変化(どのCRに配信されたか)と、各CR自体の悪化とが区別できない。

## 解法と、その理由
1. 段の不足分を広告別に割り振る(各広告の「現在の分母 × (キャンペーン基準の率 − その広告の率)」。合計が全体の不足分に一致する)。
2. 主因の広告が「新規」または「分母シェアが20pt以上増えた」ときだけ「配信構成の変化」と書く。
   シェアが変わらない広告が主因なら、その広告自体の悪化として扱う。最初はここを分けておらず、
   配信の大半を前から占めていた勝ちCR(AI動画A1)の CPM 上昇に「停止を検討」と出してしまった。
3. 主因の広告の CPA が基準以内なら停止は提案しない。
4. 勝ちCRの配信停止(費用がほぼ0)を別の検知として足した。失速の検知は配信が続いている前提なので、止まったCRを拾えない。

## うまくいかなかったこと
- 構成の変化かどうかを判定せず「主因の広告を止めろ」と出した版は、勝ちCRに停止を提案した。
- CPM の悪化は確率モデルを持たない簡易判定なのに critical にしていた。CTR 改善で相殺されて CPA がほぼ横ばいでも通知していた。
  CPA 全体が20%以上悪化していることを条件に加え、CPM は warn 止まりにした。

## 抽出したルール / ヒューリスティック
- 集計単位(キャンペーン)の率の変化を原因と書く前に、構成要素(広告)別の内訳を出し、
  「構成の変化」か「要素自体の変化」かを分ける。分けずに原因候補(LP・計測など)を書かない。
- 検知ロジックは合成データのテストだけで完成とせず、実データに1回通して、通知文を人の目で読む。
