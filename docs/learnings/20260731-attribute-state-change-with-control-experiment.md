# 「別の何かが書き換えている」を疑ったら、観測された終状態でなく対照実験で判定する

- 日付: 2026-07-31
- 種別: 誤診断の回避 / 検証設計
- 触れたファイル: `slack-inbox-to-notion/RUNBOOK.md`(既知の問題節の書き直し),
  `slack-inbox-to-notion/tools/notion-check.mjs`(検証手段)

## 問題

Slack 📥 → Notion 連携が作ったページが、いずれも「完了」になっていた。
`Slack｜` で始まるページが 4/4 完了だったため、当初は
**「登録直後に別の主体(DBオートメーション/定期処理)がステータスを書き換えている」**
と推測した。だがこれは誤りだった。実測すると自動書き換えは起きておらず、
4件は単に**人手で片付けられていた**だけだった。

## なぜ誤診断が起きやすいか

1. **終状態からの逆算は原因を一意に決めない。** 「全部が完了」は
   「自動化が書き換えた」でも「手で片付けた」でも等しく説明できる。
   観測された結果だけで犯人を名指しすると、存在しない自動化を追ってしまう。
2. **Notion は自動編集も手動編集も実行ユーザー名義で記録する。**
   ページの「最終編集者」を見ても自動/手動を区別できない(公式の既知の制約)。
   ここで手が止まり、想像で犯人を埋めてしまう。
3. コード側には更新経路が無い(呼ぶのは `databases/query` と `pages` の2つだけ)
   という事実が既にあったのに、終状態の強い印象がそれを上書きした。

## 効いた判断基準

**編集の主体を属性表示から当てられないなら、対照実験で時間軸を作る。**

- 新規に1件だけ登録し(対照)、**以後そのページに一切触れない**。
- 初期状態(ステータス・`last_edited_time`)を記録する。
- 30分以上あけて再取得し、`last_edited_time` が動いたかを見る。
  - 動かない → 外部の書き換えは無い(＝終状態は人手の結果)。
  - 動いた → 別主体が存在する。作成との時間差で候補を絞る
    (ほぼ同時＝トリガー型オートメーション、数分〜数十分後＝定期実行/手動)。

今回は 14:14 登録→14:46 再確認で INBOX・`last_edited_time` 不変。
「自動書き換え」説は棄却できた。**推測を残さず、実測に基づいて RUNBOOK を書き直した。**

## 付随して踏んだ罠：Slackリンク完全一致の偽陰性

検証ツール `notion:check` は Slackリンクの**完全一致**でページを探す。
ところが GAS は `chat.getPermalink` が返す URL を保存するため、
スレッド関連メッセージだと `?thread_ts=…&cid=…` が付く。
Slack の「リンクをコピー」で得たクエリ無し URL を渡すと完全一致が外れ、
**登録済みなのに「未登録」と偽表示される**。実際にこれで #6-media を
一度「未登録」と誤判定した。切り分けは**メッセージID(`p…` の数字)部分一致**で
再検索して確定した。検証手段自体の一致条件が、コードの保存形式とズレていないかを疑うこと。

## 一言

観測された終状態は原因を証明しない。属性表示で主体を当てられないときは、
触らず放置して時間軸の変化を見る対照実験に切り替える。
