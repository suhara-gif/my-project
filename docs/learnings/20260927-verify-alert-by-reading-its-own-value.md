# 警告に書かれている値そのものを見て、誤報を疑う

- 日付: 2026-09-27
- 種別: バグ修正 / 調査
- 触れたファイル: google-ads-mcp の ga4_sync/ga4_sync_monitor.py(parse_dt)

## 問題
GA4 同期の監視が毎朝 08:15 に「【シート鮮度NG】cw_会員id(2026-09-27 6:26:16)…」と通知していた。9/26 の時点では「本番切り替え直後だから」「閾値が厳しいのかも」と推測して [要確認] のまま置いていた。

## 文脈
警告文には最終更新時刻(当日 06:26)がそのまま載っていた。26時間以内という基準で見れば明らかに新しいので、判定ロジック側に原因があると読み取れたはずだった。

## 解法と、その理由
1. 警告に載っている値(`2026-09-27 6:26:16`)を、判定コードの `parse_dt` にそのまま通して試した。
2. `datetime.fromisoformat` は、時が0埋めされていない値を受け付けない。そのため None が返り、「鮮度NG」と判定されていた。
3. シートの FORMATTED_VALUE は時を0埋めしないので、`strptime` によるフォールバックを追加した。

## うまくいかなかったこと
初日は、原因を運用上の事情(切り替え直後・閾値の設定)と推測するだけで、コードを読まなかった。そのため誤報が1日多く続いた。

## 抽出したルール / ヒューリスティック
「NG」の警告に判定の元になった値が書かれていて、その値が基準を満たしているように見えるときは、運用の事情を疑う前に、その値を判定関数にそのまま入れて再現する。日付の解析(0埋め・区切り文字・タイムゾーン)は誤報の常連なので、最初に確かめる。
