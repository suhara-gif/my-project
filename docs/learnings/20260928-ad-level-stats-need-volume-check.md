# 広告自動判定の設計は、先に実データの件数を見てから統計手法を決める

- 日付: 2026-09-28
- 種別: 設計判断
- 触れたファイル: meta-ads-autopilot/src/meta_autopilot/stats.py, detect/funnel.py, patterns/mine.py, lifecycle/decide.py

## 問題
「広告×日で CPM→CTR→LPV率→CVR を分解して崩れを自動判定」「勝ちパターンを見つけて量産」「新CRを停止・継続・横展」
を自動化したいという依頼。構想どおり閾値ベースで作ると動くが、判定が信用できるかは件数しだい。

## 文脈
Meta Ads MCP でトヨワクの直近28日を見ると、広告約20本で CV 計約49件。上位の広告でも28日で CV 6件、
大半は 1広告1日あたり 0〜1件。この件数では広告×日の CVR・CPA は点推定がほぼノイズになる。

## 解法と、その理由
1. 率は Beta-Binomial、CPA は Gamma-Poisson(CV ~ Poisson(費用×λ))で「悪化している確率」を出し、
   確率と変化幅の両方を満たしたときだけ判定する。事前分布は目標CPAに置き、CV 0〜2 件の広告を極端に扱わない。
2. ファネル分解は対数で行う(CPA = CPM/1000 ÷ (CTR×LPV率×CVR) なので段の寄与が足し算になる)。
   件数の多い上流段は早く、CV の少ない CVR 段は遅く確信に達する。これを「早期に見られるのは上流だけ」という
   新CR判定の段階設計(費用が目標CPAの何倍か)にもそのまま使った。
3. パターン分析はキャンペーンの平均効率で期待CVを出して比べる(間接標準化)。生の CPA で比べると、
   CPA水準の良いキャンペーンに多い属性が「勝ち」に見える。組み合わせが同じ広告集合なら冗長として落とす。

## 抽出したルール / ヒューリスティック
- 広告の自動判定を設計する前に、判定単位(広告×日など)あたりの CV 件数を実データで1回数える。
  中央値が数件以下なら、点推定の閾値判定は使わず、確率ベースの比較と最低費用ガードをセットにする。
- 観察データの「勝ちパターン」は仮説として扱い、確定は同じ期間に並走させた比較で行う(Meta は配信を寄せるので交絡する)。
