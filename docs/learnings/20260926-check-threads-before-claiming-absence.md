# Slackで「届いていない」と断定する前にスレッドを確認する

- 日付: 2026-09-26
- 種別: 失敗した試み / 調査
- 触れたファイル: company/secretary/ideas/2026-09-26-slack通知整理.md

## 問題
Slackの通知量を調べた際、#ai-運用 を `slack_read_channel` で読み、ai_shain のレポートが9/19〜9/23に1本も届いていないと報告した。
しかし実際は、須原さんの依頼メッセージのスレッド内にレポートが返っていた。誤った断定をそのままユーザーに出してしまった。

## 文脈
`slack_read_channel` はチャンネル直下の投稿だけを返し、スレッドの返信は含めない。
`response_format: concise` を指定すると、「Thread: N replies」という手がかりまで消える。
ボットが依頼にスレッドで返信する運用では、チャンネル直下には失敗通知だけが残る。そのため、「失敗しか起きていない」ように見える。

## 解法と、その理由
`response_format: detailed` で読み直し、依頼メッセージに付いた「Thread: 2 replies」と ✅ リアクションを確認した。
そのうえで `slack_read_thread` を使い、代表のスレッド(9/19・9/22)を開いてレポート本文があることを確かめた。
不在の断定は、存在の断定よりも反証が1件で崩れる。したがって、先にスレッドを確認するのが最も安い手順になる。

## うまくいかなかったこと
concise 形式の一覧だけを見て、件数を数えて結論を出したこと。エラー率の分母(ボット投稿の数)も数え間違えていた(33件→正しくは35件)。

## 抽出したルール / ヒューリスティック
Slackで「〇〇が来ていない/失敗している」と書く前に、次の2つを必ず行う。
1. `response_format: detailed` で読み、該当する期間にスレッド付きのメッセージがあるか確認する
2. スレッドが1本でもあれば、`slack_read_thread` で最低1本は開いてから結論を書く
