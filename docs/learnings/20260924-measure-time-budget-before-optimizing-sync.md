# 会話1,800件の同期が回りきらない問題: 時間の使い道を実測してから、休眠会話の確認を間引く

- 日付: 2026-09-24
- 種別: 設計判断
- 触れたファイル: slack-notion-archiver/設定と同期.gs

## 問題
ユーザートークンを入れたら、対象の会話が1,847件(DM 303、グループDM 1,426、プライベートCH 88、ほかに公開CH)になった。
手動で1回実行すると `time budget reached: 27/1847`、`saved=300` で、4.5分の実行時間を使い切った。

## 文脈
最初は「会話を順に見に行く呼び出し(Slack API)の回数制限が詰まっている」と見積もっていた。
しかし実測では、見に行けた会話は27件、保存は300件だった。
1件あたり約0.9秒(Notion への書き込み、リンク取得のための Slack API 呼び出し、0.12秒の待機)かかるので、300件で約270秒になり、実行時間とほぼ一致する。
つまり時間を使っていたのは会話の確認ではなく、未保存分の書き込みだった。
それでも、未保存分を消化したあとに1,847件を毎回確認すれば15分の実行間隔を超えるので、確認の間引きは別途必要と判断した。

## 解法と、その理由
- **確認を間引く**: 会話ごとに最終発言時刻(`ACT_<id>`)を記録する。14日間発言が無い会話は、12時間に1回だけ確認する。
  - 一度も確認していない会話は、休眠かどうか分からないので毎回確認対象にする。キーが無いことを「未確認」として扱う。
  - 休眠の判定期間(14日)は、返信を探しに遡る期間(7日)より長くした。
    こうすれば、休眠中の会話に拾える返信が残っていることはない。
  - 処理順は「最近発言のある会話が先、その中では前回確認が古い順」。
    前回の続き位置を覚える方式(カーソル)をやめ、この並べ替えで順番が自然に回るようにした。
- **書き込みを速くする**: Notion に入れる「Slack Link」を `chat.getPermalink` で取らず、自前で組み立てる。
  組み立て方は `auth.test` の URL + `archives/<ch>/p<tsから点を除いたもの>`。返信なら `?thread_ts=&cid=` を付ける。
  1件ごとの Slack API 呼び出しが1回減る。組み立てられないときは従来どおり API で取る。

## うまくいかなかったこと
最初の見積もり(「API の回数制限で約200会話しか回れない」)は、実測で外れた。
実測では、時間を使っていたのは Notion への書き込みで、会話の確認はほとんど進んでいなかった。
見積もりのまま最適化していたら、書き込みを速くする手当てが漏れていた。

## 抽出したルール / ヒューリスティック
- 時間切れの対処を決める前に、ログから「処理した件数」と「保存した件数」の両方を読み、どこで時間を使ったかを実測で割り振る。
- 一覧系 API で対象が数百件を超えたら、「最近動いたものだけを毎回、それ以外は間隔を空けて見る」スケジューリングを最初から検討する。
  判定用の最終活動時刻は自前で記録し、キーが無い状態を「未確認=毎回確認」として扱う。
