# MCP 経由で作った Routine はコネクタを持たない — 安全策を指示文に入れ、検証はサブエージェントで行う

- 日付: 2026-09-26
- 種別: 調査 / 設計判断 / 失敗した試み
- 触れたファイル: second-brain/notion/compiler-prompt.md, second-brain/notion/gardener-prompt.md, second-brain/notion/README.md

## 問題
Notion の第二の脳を毎日自動で整理する実行役として、Notion カスタムエージェントは使えなかった（課金していない。2026年5月から有料クレジット制）。
代わりに Claude の Routine（`create_trigger`、発火ごとに新しいセッション）で定時実行しようとした。
- `connectors: ["Notion"]` を付けると「この組織では connectors パラメータは使えない」と拒否された。
- 付けずに作ると、Routine は作成されたが「コネクタを保存していないので、発火したセッションには mcp__* ツールが無い」という警告が出た。
- 実際に発火させると、起動したセッションのツールに Notion が含まれておらず、20秒で終わった。

## 文脈
- このセッション自身は Notion MCP を持っている。それでも Routine には引き継がれない。
- 自律実行が前提（CLAUDE.md）。ユーザーの操作を待たずに、できるところまで検証を終わらせたい。
- 実行役は Notion への書き込み権限を DB 単位で絞れない。指示文での制限と、実行ログによる巻き戻しが安全策のすべてになる。

## 解法と、その理由
1. **指示文の冒頭に「Notion が使えなければ何も書かずに終了」を入れてから発火した。**
   そのおかげで、接続なしの発火は無害に終わった（実行ログ0件、処理済み件数も変わらないことを SQL で確認した）。
2. **指示文そのものの検証は、このセッションのサブエージェントに任せた。**
   general-purpose のサブエージェントは親セッションの MCP を使える。指示文のファイルだけを読ませて実行させれば、
   Routine が本番で受け取るのと同じ条件で指示文を試せる。
3. **採点は、実行したのとは別のサブエージェントに、読み取り専用で行わせた。**
   基準は数値で事前に決めた（ルール違反0件、種別の一致率90%以上、素材本文の改変0件）。
   1周目は一致率90%のぎりぎり合格で、失敗の原因は指示文のあいまいさだった。改善案を反映した2周目は100%で合格した。
4. **Routine はスケジュールを付けない「手動起動のみ」の状態で登録した。**
   ユーザーが claude.ai の画面でコネクタを付けるまで、定時実行は有効にしない。
   接続なしで毎日空振りし、実行ログも残らない（＝動いていないことに気づけない）状態を作らないためである。

## うまくいかなかったこと
- `create_trigger` の `connectors` パラメータ：組織の設定で使えなかった。
- read_documentation の `connectors.add` は「コネクタが未接続なら接続して新しいセッションを始める」という案内だった。
  「セッションには接続があるのに Routine に渡せない」という今回の状況には当てはまらなかった。
- 1周目の実行では、個人の資産メモに判断基準が書かれているのに「記録」にしてしまい、再処理の対象から永久に外れかけた。
  「迷ったら取り返しのつく側（保留）に倒す」というルールを、指示文に明記していなかったのが原因だった。

## 抽出したルール / ヒューリスティック
- MCP 経由で Routine を作ったら、発火させる前に、結果の警告文に「stores no MCP connectors」が含まれていないかを確認する。
  含まれていたら、コネクタが必要な処理は動かない前提で進める。
- コネクタに依存する定時実行の指示文には、必ず「ツールが無ければ何も書かずに終了」を1行目付近に入れてから発火する。
- 定時実行の指示文を検証するときは、「指示文ファイルだけを読むサブエージェントで実行」→「別のサブエージェントが読み取り専用で数値基準に照らして採点」を1周とする。
  ぎりぎりの合格なら、指示文を直してもう1周回す。
- 分類ルールには「迷ったときに倒す側」を明記する。倒す側は、処理済みの印が付かず、後から取り返せる状態のほうにする。
