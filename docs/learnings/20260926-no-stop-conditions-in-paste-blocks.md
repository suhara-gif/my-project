# 貼り付け用のコマンド列に「止まる条件」をコメントで書かない

- 日付: 2026-09-26
- 種別: 失敗した試み
- 触れたファイル: company/secretary/ideas/2026-09-26-slack通知整理.md

## 問題
Mac で実行してもらう手順として、次の順に並べたコマンドブロックを渡した。
`git ls-files | grep 秘密ファイル` → `# 何か出たら push は中止` → `git push`
須原さんはブロックを丸ごと貼り付けた。grep は秘密ファイル(.env.bak.*、client_secret.json、gmail_token.json など)を大量に検出したが、その直後の git push もそのまま実行された。
リモート側の先行コミットで push が rejected されたため、偶然アップロードされずに済んだ。

## 文脈
- macOS 標準の zsh は、対話モードで `#` をコメントとして扱わない(`interactivecomments` がデフォルトでオフ)。そのため、コメント行もコマンドとして実行されてエラーになった。
- それ以前の問題として、人間は複数行をまとめて貼り付ける。条件分岐を「人が読んで判断する注釈」で表現しても、止める仕組みにはならない。

## 解法と、その理由
- 確認用のコマンドと、状態を変えるコマンド(push / 書き込み / 削除)は、**別々のブロックに分けて渡す**。確認結果を受け取ってから、次のブロックを渡す。
- どうしても1つのブロックにする場合は、`if ...; then echo 中止; else git push; fi` のように、シェル自身に判定させる。
- Mac に渡すブロックにはインラインコメントを入れない(zsh 対策)。

## うまくいかなかったこと
「↑何か出たら push は中止」というコメントによる注意書きは機能しなかった。

## 抽出したルール / ヒューリスティック
人に実行してもらうコマンドブロックでは、状態を変える操作の前に、人の判断を挟む前提を置かない。判断が必要なら、ブロックをそこで区切る。
