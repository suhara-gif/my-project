# 母艦作業は「1回・1コマンド・結果はSlack」に固定し、小出しの確認コマンドと貼り付け往復を作らない

- 日付: 2026-10-09
- 種別: 失敗した試み
- 触れたファイル: google-ads-mcp/9_uvキャッシュを空ける.command, google-ads-mcp/disk_uv_free.py, google-ads-mcp/command_lint.py, CLAUDE.md

## 問題
ディスク容量の調査・対応(母艦 Mac)で、須原さんの手戻りが多発した。外形で確認できる事実:
- 診断コマンドの案内に `git fetch && git merge` を付け忘れ、まだ母艦に無いファイルを実行させる形になった(Slack に投稿が届かず1往復)。
- 「結果は Slack に出して私が読む」と合意済みだったのに、`pgrep` / `tmutil` / `du` / `find` の出力の貼り付けを繰り返し依頼した。貼り付けた出力の一部が zsh にコマンドとして実行された(`zsh: command not found: 3036960` 等、`last` の出力混入)。害は出なかった。
- 「システムデータが100GB超で原因はスナップショット」と推定し、スナップショット削減の手順まで出した。実測ではシステムデータ 51.68GB、Time Machine のスナップショットは dataless で、外れた。
- 自動掃除ジョブを `--apply` で登録したあとで、`uv cache prune` が常駐の chroma-mcp のロックで毎回300秒待って失敗すると判明した。

## 文脈
母艦は利用者の手元でしか実行できず、私は結果を直接見られない。そのため「利用者に何を1回やってもらうか」の設計が、そのまま手戻りの数になる。コンテキスト圧縮を挟むと、会話内だけの合意(Slack で読む)は要約から薄れる。

## 解法と、その理由
5 Whys（Why3 以降は私の判断過程の推定で、検証可能なのは外形事実のみ [推定]）:

| 原因 | なぜの連鎖(要約) | 再発防止策 | 実行手順 | 横展開の確認範囲 | 完了の証跡 |
|---|---|---|---|---|---|
| C1 手作業依頼のゲートが無い | 結果が見えない→小出しコマンドで貼ってもらう→「Slack で読む」合意が会話内だけ→CLAUDE.md に依頼前のチェックが無い | CLAUDE.md に「母艦作業の依頼ルール」を追加(貼り付け依頼禁止・1回1コマンド・前提内包) | 本ノートと CLAUDE.md を更新し PR | google-ads-mcp の番号付き .command(6〜9)を規約で検査 | `command_lint.py` の PASS/EXEMPT 表、CLAUDE.md の差分 |
| C2 推定を推奨に昇格した | 計算中の2項目の残差を片方へ割当→[推定]を付けたまま手順を提示→既存の昇格ルールは文書作成時の想定で、チャット内の提案に適用しなかった | 既存ルールにチャット内の提案・コマンド案内も対象と明記 | CLAUDE.md の該当節に1文追記 | 本セッションの推奨のうち未確認前提のもの(スナップショット削減=撤回済み、uv 容量の見込み=[要確認]付き) | レビュー表(本ノート)と撤回の記録 |
| C3 実機前提を測らず本番設計した | uv の公式ドキュメントだけを根拠にジョブ化→常駐 uvx の存在・取り込み状況を読み取りで確認しなかった→launchd の PATH 問題(GAS乖離)と同型の再発 | 自動ジョブ/インストーラは、設計前に読み取り専用プローブを Slack に出す。実行系は自己更新(ff-only)で取り込み忘れをなくす | `disk_uv_free.py`(診断のみが既定)、`7_/8_/9_` に SELF_UPDATE、`command_lint.py` | 6_ は main 運用のため EXEMPT(理由つき)。launchd の PATH 前提は別ノート参照 | 自己更新の模擬テスト(クリーン=取り込む/ダーティ=取り込まない)、lint の PASS |

## うまくいかなかったこと
- 自己更新を最初は `git merge --no-edit` で入れた。第三者視点のレビューで、衝突時に merge 途中の状態を残す恐れがあると指摘され、`--ff-only`＋作業ツリーがクリーンのときだけに直した。
- ルールの追記だけでは再発する(既存の「観察昇格」ルールを今回も破った)。そのため、検査できるものは `command_lint.py` で機械化した。
- 自己更新は、利用者の手動マージという確認を外す。対象を単一ブランチ・ff-only・版の表示に限定し、`NO_SELF_UPDATE=1` で止められるようにした [実行面の残リスク: 未レビューのコードが次回実行時に動く]。

## 抽出したルール / ヒューリスティック
利用者に端末操作を頼む前に、次の3点を満たすか確認する。満たさなければ依頼しない: (1) 結果は Slack かファイルで私が読め、貼り付けを依頼しない (2) 依頼は1回・1コマンドで、前提(最新版の取り込み)をコマンド自身が内包する (3) 自動ジョブは、実機の前提を読み取り専用プローブで測って Slack に出してから設計する。
