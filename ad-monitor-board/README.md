# 広告 監視ボード

`GAS_広告実績、今年RAW` の `daily_summary`(日次・媒体×サイト別の広告実績)は数字が並んでいるだけで、
変化や異常に気づきにくい。そこで同じブックに「監視ボード」シートを追加し、**媒体×サイトごとに1行**で
「推移の折れ線」「昨日の値」「いつもとのズレ」「空欄が続いているか」「整備士CPAの変化」を並べて、
色と「判定」列で要確認の行が一目で分かるようにする。

## ボードの見方

| 列 | 内容 |
|---|---|
| 費用 推移 / 整備士 推移 | 直近28日の折れ線。空欄の日は0として描く |
| 昨日 費用 / 昨日 整備士 | 基準日(B2)の値 |
| 費用 7日平均比 | 昨日の費用 ÷ その前7日の平均。150%以上で赤、50%以下で青 |
| 整備士CPA(今) | 直近3日を除いた7日間の 費用合計 ÷ 整備士CV合計 |
| 整備士CPA(基準) | その前14日間の同じ計算 |
| 整備士CPA 比 | 今 ÷ 基準。150%以上で赤 |
| 費用 空欄日数 | 基準日から遡って何日続けて費用が空欄か。2日以上で赤 |
| 理由 / 判定 | 要確認の理由と、「正常 / 要確認 / データなし」 |

- 上部の「要確認」の件数が0なら、その日は見るべき行はありません。
- **判定は「異常」ではなく「要確認」に留めている。** 空欄の原因は、配信停止・取得漏れ・後からの一括入力・
  実測ゼロのいずれもありうるため(`company/knowledge/business.md` の「空欄の読み方」参照)。
  要確認の行は、管理画面の実数値で確かめてから判断する。
- 全期間が空欄の列(現状では `G_CWA`)は「データなし」と表示し、要確認の件数には数えない。

## 設計の判断

- **ボードは数式だけで作る。** `buildMonitorBoard()` を1回実行すると数式が入り、以後は `daily_summary` が
  更新されるたびに自動で再計算される。新しい定期実行ジョブは作らない。GASジョブが気づかれずに止まる事例が
  過去に何度もあった(7/11の集計スクリプト失敗、AIシグナルシートの停止、2026-09のカーワーク整備士CV
  アップロードの6日間停止)ため、監視する側まで同じ壊れ方をしないようにしている。
- **`daily_summary` には書き込まない。** 読み取りだけなので、既存の集計の仕組みに影響しない。
- **列は見出し名で参照する**(`MATCH`)。列が挿入・移動されても壊れない。シート参照は `INDIRECT` にしてあり、
  集計ジョブがシートを消して作り直しても `#REF!` にならない。
- **当日の行は使わない。** 最終行が今日以降の日付なら集計途中とみなし、その前の行を「昨日」にする
  (2026-09-28 時点で、最終行には3セルしか値が入っていなかった)。
- **整備士CPAは直近3日を除いて計算する。** 整備士数は後から確定する(オフラインCVのアップロード等)ため、
  直近分を入れると実際より悪く見える。
- **比較基準は14日間。** `daily_summary` には直近約31日分しか入っていないため、「除外3日 + 今7日 + 基準14日」
  で収まるようにした。
- 既存の集計スクリプトと同じ Apps Script プロジェクトに置いても名前がぶつからないよう、グローバルな名前は
  すべて `MB_` / `mb` 接頭辞にし、`onOpen` も定義していない。
- 同名の「監視ボード」シートがあっても、このスクリプトが作ったもの(A1 が「広告 監視ボード」)でなければ
  上書きせずに中断する。

## 検証したこと

- Google Sheets 上ではまだ動かしていない。実行環境が無いため、GAS の呼び出しを模擬して
  `daily_summary` の実際の見出し(2026-09-28 時点の52列)でボードを生成し、生成された数式を目視で確認した。
- 同じ判定ロジックを Python で実データ(基準日 2026-09-27)に当てはめると、15行中5行が要確認、
  1行(G_CWA)がデータなしになった。

## 前提・未確認事項

- `daily_summary` の見出しが「媒体_サイト_指標」形式であること。2026-09-28 時点の見出しで確認済み。
  例外として `I_CW_CPA整備士` などの列もあるが、ボードでは使っていない。
- 日付がA列の2行目から連続して入っていること。途中に空行があると「昨日」の位置がずれる。[要確認]
- セルの値が数値で入っているか、「38,759」のような文字列で入っているか。どちらでも計算できるよう数値に
  変換しているが、実際のシートで「昨日 費用」が `daily_summary` と一致するかをセットアップ時に必ず確認する。
- `LET` / `CHOOSEROWS` / `SEQUENCE` / `FILTER` を使っている。現行の Google スプレッドシートで使える関数だが、
  このブックで数式エラーが出ないかはセットアップ時に確認する。[要確認]
- 集計スクリプトが `daily_summary` を「消して作り直す」方式か「上書き」方式かは未確認。どちらでも
  壊れないよう `INDIRECT` にしている。

## 既知の限界と調整候補

- **曜日の影響を区別しない。** 「7日平均比」は直前7日の平均と比べるため、土日に費用が落ちる媒体
  (Indeed 等)は週明けに「平均より少ない」が出やすい。1〜2週間運用して誤検知が多ければ、比較先を
  「前週の同じ曜日」に変えるか、閾値(`MB_CONFIG.RATIO_ALERT`)を広げる。
- 閾値(±50%、空欄2日、整備士CPA 1.5倍)は仮の値。媒体ごとの普段のばらつきは見ていない。
- 整備士CVは件数が少ないため(1週間で0〜数件)、整備士CPA 比は大きく振れやすい。1〜2件の差で
  要確認になることがある。
- 折れ線は空欄を0として描くため、空欄の日は「急落」に見える。空欄かどうかは「費用 空欄日数」で見る。
