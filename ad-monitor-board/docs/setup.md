# セットアップ手順

プログラミング不要です。**まずコピーしたブックで試し、問題なければ本番に入れます。** 所要目安15分。

## 1. コピーで試す

1. Google Drive で `GAS_広告実績、今年RAW` を開き、「ファイル」→「コピーを作成」。
   名前は「【試験】GAS_広告実績」など、本番と区別できるものにする。
2. コピーしたブックを開き、「拡張機能」→「Apps Script」を開く。
   - 本番に紐づいた集計スクリプトもコピーされていることがあります。**コピー側のスクリプトは実行しないこと**
     (本番と同じ書き込み先に書き込む可能性があるため)。触るのは次の手順で追加するファイルだけです。
3. 左の「ファイル」の「+」→「スクリプト」で新しいファイルを追加し、名前を `Board` にする。
4. `ad-monitor-board/src/Board.gs` の中身を全部コピーして貼り付け、保存する。
5. エディタ上部の関数選択で `buildMonitorBoard` を選び、「実行」を押す。
   - 初回は権限の承認画面が出るので許可する。
6. ブックに戻ると、先頭に「監視ボード」シートができている。

## 2. 動作確認(ここを飛ばさない)

コピーのブックで、次の4点を確認してください。

1. **B2「基準日(昨日)」が昨日の日付になっている。** 今日の日付なら、集計途中の行を拾っています。
2. **「昨日 費用」が `daily_summary` の同じ日・同じ列と一致している。** 例: G_CW の行の「昨日 費用」と、
   `daily_summary` の基準日の行の `G_CW_費用`。0 や空欄になっていたら、数値の読み取りに失敗しています。
3. **G_CWA の行が「データなし」になっている。** 全期間が空欄の列なので、こうなるのが正しい動きです。
4. **`#ERROR!` や `#NAME?` が出ているセルが無い。** 出ていたら、そのセルの内容をメモして相談してください。

4点とも問題なければ、手順3に進みます。

## 3. 本番に入れる

1. 本番の `GAS_広告実績、今年RAW` を開き、「拡張機能」→「Apps Script」を開く。
2. 手順1の3〜5と同じように `Board` ファイルを追加して貼り付け、`buildMonitorBoard` を実行する。
   - 既存のファイル(集計スクリプト)は**編集しない**でください。`Board` を追加するだけです。
   - 名前がぶつからないよう、`Board.gs` の関数や変数は `MB_` / `mb` で始まる名前にしてあります。
3. 手順2の4点を本番でもう一度確認する。
4. 試験用のコピーは、確認が済んだら削除してかまいません。

## 使い方

- 毎朝「監視ボード」を開き、上部の「要確認」の件数を見る。0 なら見るべき行はありません。
- 黄色(要確認)の行は「理由」列を読み、管理画面の実数値で確かめてから判断する。
- **ボードは自動で更新されます。** 再実行が必要なのは、`daily_summary` に新しい媒体×サイトの列が
  増えたときだけです(`buildMonitorBoard` をもう一度実行すると、行が作り直されます)。

## 設定を変えたいとき

`Board.gs` の冒頭の `MB_CONFIG` を書き換えて保存し、`buildMonitorBoard` を再実行します。

| 設定 | 意味 | 初期値 |
|---|---|---|
| `RATIO_ALERT` | 費用の7日平均比が ±この割合 を超えたら要確認 | 0.5(±50%) |
| `BLANK_ALERT_DAYS` | 費用が何日続けて空欄なら要確認 | 2 |
| `MECH_LAG_DAYS` | 整備士CPAの計算から外す直近の日数 | 3 |
| `MECH_WINDOW_DAYS` / `MECH_BASE_DAYS` | 整備士CPAの「今」と「基準」の日数 | 7 / 14 |
| `MECH_CPA_ALERT` | 整備士CPAが基準の何倍以上で要確認 | 1.5 |

`daily_summary` は直近約31日分しか持たないため、`MECH_LAG_DAYS + MECH_WINDOW_DAYS + MECH_BASE_DAYS` は
31以下にしてください。超えると整備士CPAの欄が空欄になります。
