# .claude/ — このリポジトリのセッション設定

## セッション肥大化ガード（有効・自動）

`settings.json` の `UserPromptSubmit` フックが、プロンプト送信のたびに
`hooks/session-size-guard.sh` を呼び、セッションが一定の長さを超えたら警告を出します。

**なぜ要るか**: 1セッションが伸びるほど、毎ターンのコンテキスト再読込と
cache_write（サブスクでは1時間TTLのため 2.0x 課金）が積み上がります。
消費分析では、最も重かった1セッションだけで計測分の約41%を占めていました。

**指標は2段構え**です。

① **直近ターンの `cache_read_input_tokens`** — 毎ターン読み直しているコンテキスト量そのもの。
transcript の `message.usage` から取得します。**これが本命**で、行数よりはるかに実態に近い数字です。

② ①が取れなければ **エントリ数（行数）** へフォールバック。

| 指標 | 警告 | 強い警告 |
|---|---|---|
| ① cache_read トークン | 400,000 以上 | 700,000 以上 |
| ② エントリ数（①が取れない場合） | 300 以上 | 600 以上 |
| いずれも閾値未満／情報が取れない | 完全に無音 | — |

**ブロックはしません。** 作業を止めるのは壊れる側なので、警告のみです。
`transcript_path` が取れない・ファイルが無い・JSONが壊れている場合はすべて黙って通します。

**閾値の調整**:

```sh
export CLAUDE_SESSION_WARN_CTX_TOKENS=500000
export CLAUDE_SESSION_LOUD_CTX_TOKENS=800000
export CLAUDE_SESSION_WARN_ENTRIES=400   # フォールバック側
export CLAUDE_SESSION_LOUD_ENTRIES=800
```

**設計上の注意 — なぜ2段構えか**: ①は transcript の内部形式に依存します。公式ドキュメントは
「エントリ形式は内部仕様でバージョン間で変わる。直接パースするスクリプトは壊れる」と
明記しているため、**①が壊れたら黙って②へ落ちる**構造にしてあります。②は `wc -l` だけなので
形式変更に強く、最後の砦として残ります。

**実測の較正データ**: このフックを作ったセッションは **420エントリ / cache_read 約72万トークン**
でした。つまり毎ターン72万トークンを読み直していた計算です。既定値はここから置いた暫定値なので、
実際の表示を見て調整してください。

## コンテキスト使用率の常時表示（任意・未接続）

`statusline.sh` は現在のコンテキスト使用率をバーで表示します。
**セッションが膨らむ根本原因は「膨らんでいることが見えない」こと**なので、
閾値で鳴るフックより、常に見えるこちらのほうが効く可能性があります。

既定では接続していません。プロジェクト設定に置くと個人の statusline を
上書きしてしまうためです。使う場合は `~/.claude/settings.json` に自分で:

```json
{
  "statusLine": {
    "type": "command",
    "command": "/絶対パス/my-project/.claude/statusline.sh"
  }
}
```

表示例: `ctx [#######...] 74%`（70%以上で `ctx!` に変わります）

## 他リポジトリへの配布（`install-to.sh`）

リモートには個人設定が届かないため、カバーしたいリポジトリごとに `.claude/` の配置が要ります。
つまり複製が生じ、**複製は必ずドリフトします**。手でコピーせず、このスクリプトを使ってください。

```sh
bash .claude/install-to.sh ../gas-backup
```

- **このリポジトリの `.claude/` が正本**です。更新はここで行い、導入先では再実行して同期します
- **冪等** — 何度実行しても重複登録されません
- 既存の `settings.json` は**破壊しません**。フック配列に追記マージするだけで、
  既存の `permissions` や他のフックはそのまま残ります（上書き前に `.bak` を作成）
- 不正なJSONの `settings.json` を見つけたら中断します（壊さないため）
- 導入先に `SOURCE.md` を置き、直接編集しないよう明記します

配布先の優先順位は消費実態から: **gas-backup**（最重量セッションを含む）→ **cybozu-inhouse**。
実行後は導入先で `git diff` を確認してからコミットしてください。

## 個人設定として推奨（このリポジトリには入れていません）

消費の 82〜92% が Opus に乗っていたため、既定モデルを下げるのが最大の打ち手です。
ただし**モデル選択は個人の裁量**で、プロジェクト設定に書くとこのリポジトリを開いた
全セッションに強制されるため、ここには入れていません。`~/.claude/settings.json` に:

```json
{ "model": "sonnet", "effortLevel": "medium" }
```

Opus が要る作業（設計判断・大規模リファクタ・込み入ったデバッグ）では都度切り替えてください。

## リモートセッション（claude.ai / モバイル）での動作 — 検証済み

消費の大半はクラウドのリモートセッションです。実際のリモートコンテナ内で確認しました。

| 確認項目 | 結果 |
|---|---|
| transcript は存在するか | ✅ `~/.claude/projects/<project>/<session-id>.jsonl` に実在 |
| UserPromptSubmit フックは動くか | ✅ ハーネス自身が同イベントのフックを使用中 |
| `~/.claude/settings.json` は届くか | ❌ **存在しない**。個人設定はリモートに届かない |
| 本フックは実物の transcript で動くか | ✅ 動作確認済み |

**したがってリポジトリ側の `.claude/settings.json` が、リモートセッションに設定を届ける
唯一の経路です。** これが本フックをプロジェクト設定に置いている理由です。

## 未確認事項

- **閾値の妥当性** — 較正データは1セッション分だけです。表示を見て調整してください。
- **`autoCompactWindow` を下げる案は採用しませんでした** — 圧縮は要約のためのLLM呼び出しを
  伴うため、キャッシュ読み出し（0.1x）より高くつく可能性があり、未検証のためです。
