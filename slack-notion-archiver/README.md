# Slack Notion Archiver

Slack のメッセージを Notion データベースへ1件1ページで保存する GAS。
本体は Google Apps Script 上の「Slack Notion Archiver」プロジェクトで、このディレクトリはそのソースの控え。
GAS へは手で貼り付けて反映する(自動デプロイはしていない)。
長いコードを1ファイルに貼ると途中で切れることがあったので、GAS 側も2ファイルに分けている
(GAS はプロジェクト内の全ファイルを同じスコープで読むので、分けても動作は変わらない)。

| ファイル | 内容 |
|---|---|
| `設定と同期.gs` | 設定(`CONF`)・増分同期・過去分の一括保存。GAS 上の同名ファイル |
| `コード.gs` | Slack/Notion の API ヘルパーとテスト用関数。GAS 上の「コード」ファイル |
| `appsscript.json` | マニフェスト(変更なし) |

## 保存対象

| 対象 | 使うトークン |
|---|---|
| 公開チャンネル(Bot が自動 join) | `SLACK_BOT_TOKEN` |
| Bot が入っているプライベートチャンネル | `SLACK_BOT_TOKEN` |
| 自分の DM・グループ DM | `SLACK_USER_TOKEN`(任意) |
| 自分だけが入っているプライベートチャンネル | `SLACK_USER_TOKEN`(任意) |
| 上記すべてのスレッド返信 | 会話と同じトークン |

**Bot トークンでは人同士の DM は読めない。** Slack の仕様で、Bot が読めるのは Bot 自身が参加している会話だけ。
自分の DM を保存するにはユーザートークン(`xoxp-`)が要る。

スレッド返信は、**直近7日以内に立ったスレッド**への新しい返信を拾う(`CONF.threadLookbackSec` で変更可)。
それより古いスレッドに付いた返信は拾えない。Notion 上ではタイトル先頭に `[返信]` が付く。

## ユーザートークンの設定手順

1. https://api.slack.com/apps で既存の Slack アプリを開く
2. 「OAuth & Permissions」→「User Token Scopes」に以下を追加
   - `channels:history` `groups:history` `im:history` `mpim:history`
   - `channels:read` `groups:read` `im:read` `mpim:read`
3. 「Reinstall to Workspace」で再インストールし、表示される **User OAuth Token (`xoxp-...`)** をコピー
   (ワークスペースの設定によっては管理者の承認が要る)
4. GAS の「プロジェクトの設定」→「スクリプト プロパティ」に `SLACK_USER_TOKEN` として保存
5. GAS エディタで `testUserTokenAccess` を実行し、ログに DM の件数が出ることを確認

ユーザートークンを設定しなければ、従来どおり Bot で読める範囲だけを保存する。

**注意:** DM の内容は、この Notion データベースを見られる人全員に見える。DB の共有範囲を先に確認すること。

## 反映手順

1. GAS エディタの「設定と同期」「コード」をそれぞれ同名ファイルで丸ごと置き換えて保存(1行目が一致しているか確認)
2. (DM も保存するなら)上の「ユーザートークンの設定手順」を実施
3. 15分トリガーが既にあればそのまま。無ければ `create15minTrigger` を1回実行

既存の `LAST_TS` はそのまま引き継ぐ。初回実行時は各チャンネルが `LAST_TS` 以降から読み始めるので、
保存済みのメッセージが重複して保存されることはない。

## 進捗の持ち方(スクリプトプロパティ)

| キー | 意味 |
|---|---|
| `LAST_TS` | 旧版の全体の進捗。新版では「まだ個別の進捗が無い会話」の開始位置として使う |
| `LAST_TS_<チャンネルID>` | その会話をどこまで保存したか |
| `FAIL_<チャンネルID>` | 保存に失敗しているメッセージと失敗回数 |
| `ACT_<チャンネルID>` | その会話の最終発言時刻(返信を含む)。休眠判定に使う |

- Notion への保存に失敗したら、その会話は失敗した位置で止め、次回そこから再試行する(取りこぼさない)。
  同じメッセージで3回失敗したらそのメッセージは諦めて先へ進む(ログに `give up` が出る)
- 1回の実行が4.5分を超えたら打ち切り、残りの会話は次回に続きから処理する(GAS の6分制限対策)
- 14日間やり取りの無い会話は「休眠」とみなし、12時間に1回だけ見に行く。
  会話が約1,800件(DM・グループDMの大半が休眠)あり、毎回全部見に行くと15分で回りきれないため。
  休眠中の会話に新しい発言があった場合、保存されるまで最大12時間かかる
- 実行ごとの処理順は「最近やり取りのある会話 → 休眠中で確認時期が来た会話」。各グループ内では前回確認が古い順
- Notion の「Slack Link」は API を呼ばずに自前で組み立てる(1件ごとの呼び出しを減らして保存を速くするため)
- 直近60秒の投稿は次回に回す(Slack と GAS の時計のズレで取りこぼさないため)

## 既知の制約

- `backfillAllHistory`(過去分の一括保存)は Bot トークンのみ・返信なしの旧仕様のまま。
  Notion 側の重複チェックが無いので、保存済みの期間に対して再実行すると重複する
- ファイル添付・編集・参加通知など、種別(subtype)付きのメッセージは保存しない
  (「チャンネルにも送信」された返信だけは返信として保存する)
- 反映直後は、未保存分(旧 `LAST_TS` 以降)の取り込みで数時間は毎回時間切れになる。
  1回の実行で保存できるのは約300件(Notion への書き込みが律速)。残りは次回に持ち越され、取りこぼしはしない
